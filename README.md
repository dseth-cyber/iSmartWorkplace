# iSmart Workplace 3.8.9 — ฟังก์ชันและคู่มือเริ่มใช้งาน

iSmart Workplace รวม **จัดการไฟล์ Backup / Cleanup / Copy / Sync** และ **แชท LAN ในองค์กร** ในโปรแกรมเดียว ใช้ภาษาไทยหรืออังกฤษและธีมสว่างหรือมืดได้ รุ่นนี้มีตัวติดตั้งแยกตาม Windows; เลือกให้ตรงกับระบบก่อนติดตั้ง

> สถานะการทดสอบ: ตัวติดตั้งทั้งสามรุ่นผ่านการตรวจไฟล์และเปิดโปรแกรมบนเครื่องพัฒนา แต่ยังไม่ได้ทดสอบการติดตั้งทับ/ถอน 3.8.9 หรือ Incremental Backup บนเครื่อง Windows 7/10 32-bit เป้าหมายจริง โปรดทดสอบกับข้อมูลสำเนาก่อนใช้กับข้อมูลสำคัญ

## เลือกตัวติดตั้ง

| ระบบปฏิบัติการ | ไฟล์ Setup | สิ่งที่ติดตั้งได้ |
| --- | --- | --- |
| Windows 10 รุ่น 1809 ขึ้นไป 64-bit หรือ Windows 11 64-bit | `iSmartWorkplace-Setup-3.8.9-Windows-x64.exe` | Client และ **Directory Server** แบบเลือกเพิ่ม |
| Windows 10 รุ่น 2004 ขึ้นไป 32-bit | `iSmartWorkplace-Setup-3.8.9-Win10-x86.exe` | Client |
| Windows 7 **Service Pack 1** 32-bit | `iSmartWorkplace-Setup-3.8.9-Win7-x86.exe` | Client |
| Windows 7 SP1 64-bit | Setup `Win7-x86` ผ่าน WOW64 | Client 32-bit; ยังไม่ได้ทดสอบเครื่องจริงรุ่นนี้ |

Windows 7 ไม่มี Service Pack 2 หรือ 3 อย่างเป็นทางการ รุ่น Win7 ต้องมี SP1 และอัปเดตระบบที่จำเป็น ตัวติดตั้ง x86 ไม่มี Directory Server; เครื่องแม่ข่ายใช้ Windows x64 รุ่นที่รองรับ โปรแกรมไม่ต้องติดตั้ง Python แยก หากใช้โปรแกรมแบบไม่ติดตั้ง ต้องคัดลอก **ทั้งโฟลเดอร์** ของรุ่น x86 ไม่ใช่เฉพาะไฟล์ `.exe` อย่าเปิดหลายรุ่นพร้อมกัน

ตัวติดตั้งที่สร้างไว้ใน source อยู่ที่ `artifacts/release-3.8.9/Setup/`; ตรวจค่าใน `SHA256SUMS.txt` ซึ่งอยู่ในโฟลเดอร์เดียวกันก่อนส่งต่อให้เครื่องอื่น

## 1. จัดการไฟล์

| งาน | การทำงาน |
| --- | --- |
| Cleanup | ลบไฟล์เก่าตามวันที่สร้างหรือแก้ไขล่าสุด เลือกถังขยะหรือลบถาวร และเลือกลบโฟลเดอร์ย่อยที่ว่างได้ |
| Copy | คัดลอกไฟล์ทุกชั้น ต้นทางไม่หาย เลือกข้ามหรือแทนที่ไฟล์ซ้ำ |
| Backup | สร้างชุดสำรองพร้อมตรวจ SHA-256; ตั้งเก็บชุดตามอายุหรือจำนวน และเลือก ZIP ได้ในแบบ Full |
| Sync | ซิงก์ทางเดียวจากต้นทางไปปลายทาง ตรวจ SHA-256 ก่อนแทนที่ไฟล์ต่างกัน; ค่าเริ่มต้นไม่ลบไฟล์ส่วนเกิน |

**Full Backup** เป็นค่าเริ่มต้น สำรองเป็นชุดแยกโฟลเดอร์ แต่ละชุดที่โปรแกรมสร้างถูกลงทะเบียนใน SQLite เพื่อให้การเก็บกวาดชุดเก่าตรวจขอบเขตได้ หากเปิดเก็บชุดตามอายุ/จำนวน โปรแกรมลบเฉพาะชุดที่ตรวจสอบและลงทะเบียนไว้หลังสร้างชุดใหม่สำเร็จ

**Incremental Backup (เลือกเปิดเองใน 3.8.9)** เก็บเนื้อหาไฟล์ใหม่โดยอ้าง SHA-256 และสร้างจุดกู้คืนที่มีรายการไฟล์ครบทุกครั้ง กู้คืนไปยังโฟลเดอร์ `Restored-*` ใหม่โดยไม่เขียนทับของเดิม ไม่ใช้ร่วมกับ ZIP การลบจุดกู้คืนเก่า **ไม่ลบเนื้อหาในคลังและไม่คืนพื้นที่ทันที**; ยังไม่มีระบบลบวัตถุที่ไม่ถูกอ้างถึงโดยอัตโนมัติ อ่าน [รายละเอียดและข้อจำกัด Incremental](docs/INCREMENTAL-BACKUP-PLAN.md) ก่อนใช้งานจริง

ทุกงานมี **ทดลองสแกน** ก่อนรันจริงได้ การลบ/แทนที่/เก็บกวาดที่มีผลถาวรมีหน้าต่างยืนยัน และอาจต้องพิมพ์คำตามชนิดงาน (`DELETE`, `COPY`, `BACKUP`, `SYNC`) โปรแกรมคัดลอกผ่านไฟล์ชั่วคราวและตรวจ SHA-256, ปฏิเสธโฟลเดอร์ระบบ/ทางผ่าน link หรือ junction ที่เสี่ยง และไม่ลบต้นทางใน Copy, Backup หรือ Sync

ตั้งเวลารายวัน รายสัปดาห์ หรือทุก N ชั่วโมง พักคิวหรือหยุดงานได้ ดู Log/ประวัติและส่งออก CSV ได้ โปรแกรมต้องเปิดอยู่และเครื่องต้องไม่หลับจึงจะรันตามเวลา งานทำทีละงานตามคิว การสำรองไฟล์ฐานข้อมูลที่กำลังถูกโปรแกรมอื่นเขียน **ไม่รับประกันความสอดคล้องแบบ transaction/VSS**; ให้ปิดงานต้นทางหรือใช้วิธีสำรองเฉพาะของระบบนั้นก่อน

**เริ่มทำงาน Backup:** เปิด `โฟลเดอร์และตารางเวลา` → เพิ่มงาน → เลือกชนิดและต้นทาง/ปลายทางที่แยกจากกัน → เริ่มด้วย `ทดลองสแกน` → ตรวจ `ประวัติการทำงาน → ดูรายละเอียด / CSV` → ค่อยเปิดรันจริงและตารางเวลา หากเป็น Incremental ให้ทดลองกู้คืนหนึ่งจุดลงโฟลเดอร์ใหม่ก่อนใช้งานประจำ

## 2. แชท LAN ในองค์กร

- ส่งข้อความตัวต่อตัว กลุ่มที่สร้างเอง สาขาจากโปรไฟล์ และประกาศถึงทุกคน; กลุ่มที่สร้างเองคุยโต้ตอบได้ ส่วนประกาศถึงทุกคน/สาขาเป็นทางเดียว สมาชิกทั่วไปอ่านและดาวน์โหลดได้ แต่ส่งประกาศต้องได้รับสิทธิ์
- Admin จัดการสมาชิก ระงับ/เปิดใช้/เลื่อน/ถอนบทบาท ลบทะเบียนสมาชิก และให้สิทธิ์ผู้ส่งประกาศได้ Admin ส่งประกาศทุกคน/ทุกสาขาอัตโนมัติ และไม่สามารถถอน Admin คนสุดท้ายได้ ป้ายบทบาทกับช่องค้นหาชื่อ/บทบาทอยู่ในหน้ารายชื่อและจัดการสิทธิ์
- แนบไฟล์ รูป วิดีโอที่รองรับ สติกเกอร์ และ Emoji; มีภาพย่อ/แกลเลอรี/ภาพตัวอย่างวิดีโอ แชร์หรือบันทึกไฟล์และเปิดโฟลเดอร์ได้ ส่งหลายไฟล์เป็นคิวชุดละ 10 พร้อมสถานะ ส่งไม่ถึงขณะปลายทางออฟไลน์จะรอตามคิวและส่งต่อเมื่อออนไลน์
- แชทแยกหน้าต่างได้; มีตอบกลับ แชร์ เรียกคืนข้อความที่ส่ง และลบข้อความเฉพาะเครื่องเรา แสดงสถานะถึงปลายทางกับอ่านแล้วแยกกัน; แจ้งเตือนผ่าน Tray พร้อมปิดเสียงห้องได้
- โทร **เสียง** ผ่าน WebRTC ใน LAN ได้ ตั้งค่า STUN/TURN สำหรับโทรข้ามเครือข่ายได้เมื่อองค์กรมี Server นั้นเอง โปรแกรมไม่ได้ให้บริการ TURN และไม่มีการโทรวิดีโอ
- เนื้อหาข้อความ/ไฟล์ถูกเข้ารหัสระหว่างเครื่อง Directory Server เก็บรายชื่อ กุญแจสาธารณะ กลุ่ม สถานะ และกล่องพัก **ซองข้อมูลเข้ารหัสชั่วคราว** สำหรับ Relay เมื่อส่งตรงไม่ได้; Server ไม่มีเนื้อหาแชทแบบอ่านได้หรือกุญแจถอดรหัสของผู้ใช้ แต่ยังเห็น metadata ดังกล่าว การเข้ารหัสนี้ยังไม่ได้ผ่านการตรวจสอบโปรโตคอลจากภายนอก และไม่ใช่ Signal/ไม่มี Double Ratchet
- เก็บประวัติและไฟล์แนบเก่าแบบกำหนดอายุได้ (ค่าเริ่มต้นในหน้าตั้งค่า 3 เดือน แต่ต้องเปิดและยืนยันก่อนระบบลบอัตโนมัติ) การลบข้อมูลในเครื่องเราไม่ลบสำเนาของผู้รับหรือไฟล์ที่เคยบันทึกแยกออกไป

### ขีดจำกัดปัจจุบัน

| รายการ | ขีดจำกัด |
| --- | --- |
| เครื่องลงทะเบียนใน Directory Server | 1,000 เครื่อง |
| กลุ่มที่สร้างเอง | 100 กลุ่ม; สมาชิกต่อกลุ่มไม่เกิน 1,000 เครื่อง |
| การส่งข้อความหนึ่งครั้ง | สูงสุด 100 **เป้าหมาย** (หนึ่งกลุ่ม/สาขานับเป็นหนึ่งเป้าหมาย แม้มีสมาชิกหลายร้อยคน) |
| ไฟล์แนบ | 1–50 ไฟล์ต่อครั้ง, ไม่เกิน 50 MB **ต่อไฟล์**; ส่งเป็นคิวชุดละ 10 |
| ข้อความ | สูงสุด 16,000 ตัวอักษรต่อข้อความ |
| ข้อมูลแชทในเครื่อง | สูงสุด 10,000 ข้อความและไฟล์แนบรวม 1 GB ต่อเครื่อง |
| คิวส่งออก | 5,000 รายการส่งถึงผู้รับ (deliveries); ส่งกลุ่มใหญ่หลายไฟล์อาจเต็มคิวได้ |
| Relay บน Server | ซองเข้ารหัสค้างได้สูงสุด 200 รายการต่อผู้รับ และหมดอายุหลัง 14 วัน |

รองรับภาพ PNG/JPG/GIF/BMP/WEBP/TIFF, เอกสาร PDF/DOCX/XLSX/PPTX, TXT/CSV/JSON/XML/MD/LOG, เสียง MP3/WAV/M4A และวิดีโอ MP4/MOV/WEBM/MKV ตามตัวตรวจชนิดไฟล์ ไม่รับ EXE, ZIP ทั่วไป, DOC/XLS/PPT รุ่นเก่า, HEIC/HEIF หรือไฟล์ที่ตัวตรวจปฏิเสธ การตรวจชนิดไฟล์ **ไม่ใช่ Antivirus** และไม่ได้รับประกันว่าไฟล์ปลอดภัย

จำนวนเครื่องที่รองรับเป็น **เพดานในโค้ด ไม่ใช่ผลรับรองประสิทธิภาพพร้อมกัน 1,000 เครื่อง** ความเร็วขึ้นกับ CPU/RAM, เครือข่าย, ขนาดไฟล์ และจำนวนผู้รับ; ควรทดสอบกับจำนวนเครื่องจริงก่อนใช้งานวงกว้าง

## 3. ติดตั้งและเชื่อมต่อ Server / Client

**เครื่องแม่ข่าย:** ติดตั้ง Setup `Windows-x64` โดยเลือก `Workplace client and Directory Server` (ตัวเลือก Server อยู่ใน Setup x64 เท่านั้น) ปิด Server รุ่นเก่าก่อนติดตั้ง แล้วเปิด `iSmart Workplace Directory Server` จาก Start Menu หรือ `iSmartWorkplace-Server.exe` ค้างไว้; จะย่อ Console ไป Tray ได้ Server **ไม่ใช่ Windows Service** และไม่ทำงานหลังออกจากบัญชี Windows โดยอัตโนมัติ ข้อมูล Server อยู่ที่ `%USERPROFILE%\iSmartWorkplace-Server` โดยค่าเริ่มต้น; เก็บโฟลเดอร์นี้และใบรับรองไว้เมื่ออัปเกรด อย่าลบหรือสร้าง Server ใหม่แทนเพื่อแก้ปัญหาเวอร์ชัน

**เครื่องลูก:** ติดตั้ง Setup ให้ตรงระบบ แล้วเปิดโปรแกรม หากอยู่ใน LAN ที่เชื่อถือได้และอนุญาตการค้นหา Server โปรแกรมจะค้นหาและเชื่อมต่ออัตโนมัติ โหมด Server เริ่มต้นอนุญาตเครื่องบน private LAN ลงทะเบียนโดยไม่ต้องใช้รหัสเชิญ (**trust on first use**); หากต้องจำกัดสมาชิก ให้เปิด Server ด้วย `--require-invite` และเก็บรหัส Admin เป็นความลับ ตรวจชื่อ/รูปในโปรไฟล์ก่อนเริ่มแชท

**อัปเกรดรุ่น:** ปิดโปรแกรมเดิมจาก Tray รวมทั้ง Directory Server ที่กำลังรัน แล้วติดตั้งรุ่นใหม่บนเครื่องแม่และลูก; หากแก้บทบาทแล้วขึ้น `Unknown action` ให้ตรวจว่า **process Server ที่กำลังรัน** เป็นรุ่นใหม่ ไม่ใช่อัปเดตเฉพาะ Client การอัปเกรด Server เดิม **ไม่ต้องกด “ล้างการลงทะเบียนเครื่องนี้”** หรือเปลี่ยน data directory; การล้างการลงทะเบียนใช้เมื่อย้ายไป Server คนละเครื่อง/คนละใบรับรองเท่านั้น และการกลับไป Server เดิมอาจขึ้น `Identity already registered`

ดูขั้น Firewall, โหมดเชิญ และการแก้ปัญหาใน [คู่มือ LAN](LAN-CHAT-GUIDE.md)

### เชื่อมต่อเองเมื่ออยู่คนละ VLAN

เปิด `แชทในองค์กร → เมนูสามจุด → เครือข่าย / เชื่อมต่อ Server` แล้วกรอกค่า:

| ช่อง | ค่าเริ่มต้น/ตัวอย่าง | วิธีใช้ |
| --- | --- | --- |
| IP ของ Server | `192.168.x.x` | ใส่ IPv4 จริงของเครื่องแม่ข่าย |
| พอร์ต Server | `48731` | ต้องตรงกับพอร์ต HTTPS ของ Directory Server |
| SHA-256 ของ Server | 64 ตัวอักษรฐานสิบหก | คัดลอกจาก Console ของ Server แล้วตรวจผ่านช่องทางที่เชื่อถือได้ |
| IP เครื่องนี้ | `0.0.0.0` | ผูกทุกการ์ดเครือข่าย; เลือก IP เฉพาะเมื่อฝ่าย IT ต้องการ |
| พอร์ตรับข้อความ | `48733` | พอร์ต TCP ตั้งต้นสำหรับรับข้อความ/ไฟล์ตรงจากเครื่องอื่น |
| ตรวจ SHA-256 กับผู้ดูแลแล้ว | ติ๊กถูก | ยืนยันก่อน `บันทึกและเชื่อมต่อ` |

ให้ฝ่าย IT อนุญาต **TCP 48731 และ UDP 48732 ไปยัง Server**, และ **TCP พอร์ตรับข้อความของ Client** ระหว่างเครื่องผู้ใช้ตามเครือข่ายที่ต้องสื่อสารกัน โปรแกรมไม่เปิด Firewall เอง หาก P2P ไม่ถึง จะลอง Relay แบบเข้ารหัสผ่าน Server แต่ Relay มีเพดานและวันหมดอายุ ไม่รับประกันส่งไฟล์จำนวนมากให้ผู้รับที่ออฟไลน์นาน การตั้งค่า STUN/TURN สำหรับโทรเป็นอีกส่วนหนึ่ง
